# 업무일지 2026-10-17 — HOF-Net-R 성능 열세 원인 진단 (시드 42 고정)

## 1. 작업 요약
- 사용자 요청 : 시드를 42로 고정해 HOF-Net-R 이 LGBM v4 보다 구위 지표(ρ whiff)가 낮은 원인을 가리는 실험을 하고, 결과를 보고서로 작성
- 가설 6개(H1 데이터 양, H2 조기 종료·학습 부족, H3 구종 입력, H4 학습 목적, H5 구조·용량, H6 distillation)를 실험 12개로 확인했다. GPU(RTX 4070 Ti)로 전체 **8.8분**
- 보고서 : Claude Docs 「HOF-Net-R 성능 열세 원인 진단」 https://claude.ai/code/artifact/260a1458-bf16-4dd9-b955-44eeb6a80802 (차트 3개 : 학습 곡선, epoch별 ρ·RMSE, 실험별 LGBM 대비 차이)
- 이전 보고서 「구위 모델 선택 검토」의 TreeSHAP 문구 보정 : "선택이 없다" → "학습 데이터 전체가 트리 안에 기준으로 고정돼 고를 필요가 없고 항상 같은 답"

## 2. 생성/수정한 파일
- `hofnet_diag_experiment.py` (신규) : `--runs base,h1,...,h6`, `--smoke`. 실험별 결과를 `outputs/hofnet_diag/runs/*.json` 에 저장하고, 있으면 건너뛴다(재개)
  - 데이터·split·변수는 `hofnet_r_experiment.py` 1절, 구위 지표는 `hofnet_experiment.py` 4절 exec 로 같게
  - 기준선 학습은 `hr.fit_mean` 그대로 호출. 조기 종료 끄기·cosine·SWA·epoch 콜백은 스크립트 안의 `fit_mean_ext` 로 처리해 `hof_net_r.py` 는 바꾸지 않았다 (계획의 "fit_mean 선택 인자 추가" 대신. 웹 어댑터 영향 없음)
  - bootstrap : 투수 군집 재표본 1,000개를 한 번 만들어 모든 실험에 같이 적용 → LGBM 대비 차이 CI
- `outputs/hofnet_diag/` : `results.csv`, `epochs.csv`, `pt_bias.csv`, `diag_log.txt`, `runs/`
- `.gitignore` : 새 스크립트와 `outputs/hofnet_diag/*.csv|_log.txt` 허용

## 3. 주요 결과 (검증 투수×구종 ρ(구위, whiff%), LGBM v4 = 0.717)
| 실험 | P1 (MSE 평균) | P4 (ZIB) | 비고 |
|---|---|---|---|
| 기준선 | 0.681 | 0.704 | P4 차이 −0.013, CI [−0.038, +0.013] |
| H1 데이터 10/25/50% (HOF P1) | 0.595 / 0.647 / 0.664 | — | LGBM 0.641 / 0.680 / 0.704, 격차 0.03~0.05 로 일정 |
| H2 30 epoch (조기 종료 없음) | 0.681 | 0.704 | epoch별 ρ 표준편차 0.021, corr(RMSE, ρ) −0.15 |
| H2 cosine + SWA | 0.684 | 0.714 | epoch별 ρ 표준편차 0.012 |
| H3 구종 입력 | 0.691 | 0.707 | 구종별 치우침 줄지 않음 |
| H4 ZIB end-to-end | — | 0.707 | |
| H5 일반 MLP / 큰 HOF | 0.694 / 0.654 | 0.684 / 0.712 | 잡음 범위 |
| H6a 증류 (같은 표본) | 0.710 | 0.713 | LGBM 예측 재현 R² 0.94 |
| H6b 증류 (학습기간 비-waste 505,302구) | **0.716** | 0.715 | 차이 −0.001, CI [−0.007, +0.004], 재현 R² 0.96 |

- 결론 : 주 원인은 **잡음 큰 라벨에서 작은 신호를 안정적으로 학습하지 못하는 것(추정 분산)**. 표현력은 충분하다(증류로 LGBM 수준). 데이터 양은 부분적(표본 효율 차이)이고, 조기 종료·구종·목적·구조는 원인이 아님
- 이전 설명 정정 : "ZIB 목적 불일치"는 틀림(P4 > P1). "구종 경계 학습"은 근거 없음(치우침 방향이 실행마다 바뀜)
- 같은 시드 42 라도 GPU 학습(P4 0.704)과 이전 PC CPU 학습(0.701)이 다르다. 첫 epoch 부터 경로가 갈라짐

## 4. 결정 사항과 이유
- 평가 헤드는 P1·P4 둘 다 : P4 는 실험 간 차이를 줄여 보여서 원인 판별은 P1 이 더 선명
- 판단 기준 : 시드 잡음(5시드 P4 표준편차 0.016)보다 큰 차이 + bootstrap CI. bootstrap 은 평가 표본 불확실성만 반영하므로 시드 잡음 기준을 우선

## 5. 이슈 / 미해결
- 전체 실행 첫 시도에서 2024 `waste` 결측 1건 때문에 `to_numpy(bool)` 오류 → 결측은 점수 제외로 처리(`fillna(True)`, 기존 `where(~waste)` 와 같은 의미)
- 모든 결론이 시드 42 하나 기준. 5시드 확인 필요

## 6. 다음 작업 (후보)

- 평균이 LGBM 과 같고 표준편차 ≤ 0.005 이면 웹 실험 모델 교체 검토 (단 증류 모델은 LGBM 을 따라 하므로 '두 번째 의견' 가치는 줄어듦)

## 7. 추가 실험 : cosine + SWA 15 epoch (h2b_cos_swa15)
- 사용자 방침 : 시드는 42 로만 실험한다 (5시드 확인은 하지 않음)
- 동기 : h2_cos_swa(30 epoch, 마지막 10 epoch 평균)는 epoch 7 이후 과적합 구간까지 평균해 홀드아웃 RMSE 0.16913, 예측력 0.707 로 나빠졌다 → 학습을 15 epoch 로 줄이고 마지막 5 epoch(11~15)를 평균
- 구현 : `run_hof(..., epochs=)` 인자 추가, `--runs h2b`. GPU 약 40초
- 결과 (LGBM 0.717)

| 실험 | P1 ρ | P4 ρ | P4 RMSE | P4 예측력 |
|---|---|---|---|---|
| 기준선 | 0.681 | 0.704 | 0.16825 | 0.752 |
| cosine+SWA 30 epoch | 0.684 | 0.714 | 0.16874 | 0.738 |
| cosine+SWA 15 epoch | 0.679 | 0.702 | 0.16837 | 0.743 |

- 해석 : 과적합을 줄이니 RMSE 는 기준선 수준으로 돌아왔지만 ρ 개선(+0.010)도 사라졌다. 30 epoch 판의 개선은 시드 잡음 범위의 운이었을 가능성이 크다 → 학습 스케줄 조정은 개선책에서 뺀다
